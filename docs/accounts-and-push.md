### Phone push notifications (Oct 2026, iPhone and Android app only)
A new row in `notifications` (friend request, friend accepted) fires the trigger `private.notify_push()` (schema.sql), which calls the Supabase Edge Function `push` (`supabase/functions/push/index.ts`, deployed by pasting it into Edge Functions > push in the dashboard, **Verify JWT OFF**, the shared secret is the check) with the header `x-push-secret`. The function sends through APNs (ES256 JWT from the `.p8` key, production host first then sandbox) and FCM v1 (service-account OAuth) to every row of `push_tokens` for that user and deletes tokens the services report dead. Secrets (Edge Functions > Secrets, never in the repo): `PUSH_SECRET` (the same value as `private.config.push_secret`), `APNS_KEY`, `APNS_KEY_ID` (JXW82DDZ85), `APNS_TEAM_ID` (7L7SG5VT23), `APNS_TOPIC` (com.tracksidepass.app), `FCM_SERVICE_ACCOUNT` (Firebase project `trackside-pass-a3554`). Check the setup any time with the `{"ping":true}` call (see the function) from the SQL editor: `select net.http_post(url := '.../functions/v1/push', headers := jsonb_build_object('Content-Type','application/json','x-push-secret',(select value from private.config where key='push_secret')), body := '{"ping":true}'::jsonb);` then `select content from net._http_response order by id desc limit 1;`. Client: `@capacitor/push-notifications`, `pushOn/pushState` in `js/account.js` (one-time offer after the profile is created, a switch in Account, tokens registered with `register_push_token`, removed on sign-out); iOS `App.entitlements` + AppDelegate hooks; Android needs `android/app/google-services.json` (gitignored: download it again from the Firebase console, package com.tracksidepass.app). The Apple `.p8` and the Firebase service-account JSON are secrets kept outside the repo. **The APNs key must be created with Environment "Sandbox & Production"** (Keys > + > APNs > Configure; the environment cannot be changed afterwards): a sandbox-only key made every TestFlight/App Store phone fail with `403 BadEnvironmentKeyInToken` (shown as `"retry"` in the function's `sent` result and in Edge Functions > push > Logs) until it was replaced on Oct 24 2026 (secrets `APNS_KEY`, `APNS_KEY_ID`, then Deploy).

**Thursday pick reminder** (Oct 21 2026): pg_cron (job `pick-reminders`, `0 16 * * 4` UTC = noon New York, created by the last DO block of the push section in `schema.sql`) POSTs `{"picks":true}` to the `push` edge function, which calls `public.pick_reminder_targets(p_day)` (service role only) and sends "Lock in your picks" to every registered phone of a player who has not made 3 picks in some class of a game whose Thursday-on-or-before-the-event-start is today and whose race has not started; `profiles.pick_remind` (RPC `set_pick_reminders`, driven by the Settings > Pick reminders switch) opts out; tapping it opens the Podium tab (`pushNotificationActionPerformed` in `js/account.js`, data.type `pick_reminder`). **Followed series only** (Oct 26 2026): the phone sends the game series of the series you follow (`followedGameSeries()` = `guide||id` of each followed CHAMPS entry, i.e. the `s` of `data/entries.js`) with `set_pick_series()` into `profiles.pick_series` (`pickSeriesSync` in `js/app.js`: after every passport sync and when you follow/unfollow a series; cached in `K.pickSeries` with the account id; the RPC returns false when there is no profile yet so it is retried), and `pick_reminder_targets()` skips games whose series is not in it (NULL = never sent, e.g. an older app: every game, as before); the local Thursday fallback uses the same list. Needs `schema.sql` re-run; no edge function change. It does NOT write to `notifications` (those show in the in-app inbox). Without sign-in or phone notifications the app falls back to a local Thursday 12:00 notification (`schedulePickReminders` in `js/app.js`); with both on, only the server one is sent. Needs the `games` rows (`tools/sync_games.mjs`) and a re-deploy of the edge function after changing it. Check the job: `select * from cron.job;` and `select * from cron.job_run_details order by start_time desc limit 5;`.

## Weather (Oct 24 2026)
The app asks our server (`/api/weather`, `netlify/functions/weather.mjs`) for a track's forecast; the server downloads it from Open-Meteo at most once every 10 minutes per track (Cloudflare cache, lat/lon rounded to 0.01) and every phone shares that copy. `wxFetch()` in `js/app.js` falls back to Open-Meteo directly if the server cannot be reached. The answer keeps Open-Meteo's JSON shape: to change provider (Open-Meteo's commercial plan or Apple WeatherKit, needed once the app is sold: the free Open-Meteo plan is non-commercial only), rewrite only `forecast()` in `weather.mjs` to return the same fields. **Apple WeatherKit** (Oct 24 2026): `weather.mjs` uses it when the Worker has the secrets `WEATHERKIT_KEY` (the .p8 file's text), `WEATHERKIT_KEY_ID`, `WEATHERKIT_TEAM_ID` (7L7SG5VT23) and `WEATHERKIT_SERVICE_ID` (com.tracksidepass.app, an App ID with the WeatherKit capability); without them, or if Apple fails, it serves Open-Meteo exactly as before. `fromApple()` converts Apple's answer into Open-Meteo's shape (C to F, km/h to mph, UTC to the track's local time, Apple condition names to WMO codes; Apple's next-hour rain is only available in some countries, elsewhere the 15-minute rain line is borrowed from Open-Meteo). `data._src` is `apple` or `open-meteo`; the weather sheet shows "Forecast by Apple Weather" with a link to https://weatherkit.apple.com/legal-attribution.html (Apple's terms require attribution). Free allowance: 500,000 calls a month with the developer membership; the 10-minute per-track cache keeps us far below. Create the key in developer.apple.com > Certificates, Identifiers & Profiles > Keys with WeatherKit ticked (the APNs key cannot be reused for it). Check the source with `curl 'https://tracksidepass.com/api/weather?lat=30.13&lon=-97.64&tz=America/Chicago' | head -c 200` (the answer starts with `{"_src":"apple"`).
The rain radar (RainViewer, `openRadar()`) is still fetched by the phone directly; check its commercial terms before a paid launch.

**Rain alerts** (Oct 24 2026): pg_cron job `rain-alerts` (every 5 minutes, end of the rain section of `schema.sql`) POSTs `{"rain":true}` to the `push` edge function, which calls `rain_candidates()` (service role): push tokens of players with a passport stamp whose `at` is within the last 14 hours (checked in at the track), `profiles.rain_alerts` on (Settings > Rain alerts, RPC `set_rain_alerts`) and no alert for that track in 3 hours (`rain_alerts_sent`). For each track it reads `https://tracksidepass.com/data/<id>.js` (geo, tz, short name) and `/api/weather` (same cached Apple answer the app uses) and `rainSoon()` (same file) decides: dry now, wet bucket starting within 20 minutes. Sends "Rain at <track>" and records it with `rain_mark()`. Tapping opens the track (`rain_alert` in `js/account.js`). Honest limits: only signed-in players with push on who checked in; the forecast is a model (Apple's next-hour rain in the US, Australia, Japan and a few other countries; Open-Meteo's 15-minute model elsewhere), not live radar. Check: `select * from cron.job_run_details order by start_time desc limit 5;`, and call the function by hand with `{"rain":true}` to see `{"rain":{"candidates":N,"tracks":{...}}}`. Re-deploy the edge function after editing it.
