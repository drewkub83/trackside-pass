## What to watch, every week, for every series (Oct 21 2026)
`node tools/due_updates.js [--now ISO] [--text]` reads the schedules in `data/*.js` and `data/watch.js` and lists what is due: `preview` (the series races at a track within 8 days and has no entry for the event) and `after` (sessions of a series ended, 20 minutes to 48 hours ago, since the newest entry's `at` stamp, else `from`, else the event day; the last race of an event is skipped because results, standings and the podium game are written by `tools/auto_update.py`). It also prints `suggestedFrom` (14 hours before the newest session ended, so the entry shows in every time zone at once). A third kind, `refresh` (Oct 26 2026): a series' NEXT event already has a preview entry, but the series raced somewhere else after it was written (e.g. the Mexico City preview written before Austin) and that race's results are in `data/results.js` and it ended 6 hours to 7 days ago: the routine writes a NEW preview for the next event that starts from what just happened (`from` = the day it is written); the new entry's `at` makes it not due again, so it fires once after every race weekend (Sunday night to Monday). The recurring cloud routine "Trackside Pass: What to watch dispatcher" (hourly, Thursday to Monday, UTC `20 * * * 4,5,6,0,1`, claude.ai/code/routines) runs it, stops at once when nothing is due, and otherwise writes one NEW entry per due item (appended at the END of `WATCH` in `data/watch.js`: the app takes the newest entry per series whose `from` has arrived, and the later one in the array wins a tie; give every entry `at:"<ISO UTC when written>"`), validates, commits and pushes. Entries follow the accuracy rule (official series pages first; if the session results are not published yet, do nothing and let the next hourly run retry; after 24 hours write a short entry that says so). **Results** (Oct 24 2026): a second cloud routine, "Trackside Pass: Results" (hourly Thursday to Monday at :56 UTC, created by a Claude session; it fires into its own long-lived cloud session "Trackside Pass: Results (hourly)", which has the repository attached: routines created from a chat start WITHOUT the repository, so a fresh session per run cannot work; it runs `node tools/due_updates.js --results`, and the What to watch routine never sees these items) writes `results` items: a race of a series without `autoResults` (data/series.js; only F1, IndyCar, GT World Challenge America and Europe have automatic results) that ended 20 minutes+ ago and has no data/results.js entry; it writes the finishing order from a published race report (series/Porsche/IMSA news, sportscar365, RACER; never live timing) with `race:"<session name>"`, retrying hourly until a report is out. Meanwhile the hub's "How it finished" card says when the result is expected and links to the series' live timing for the final order. Check it with `RemoteTrigger list_runs` / `get_run_log` or run the script by hand; the old one-off Portimao/Barber routines and Mac tasks are finished and disabled.

## Scheduled routines and automation
Long-term goal: the app runs without the owner's computer. Cloud routines (claude.ai/code/routines, run in Anthropic's cloud, push to `main`) are the durable mechanism; desktop scheduled tasks only run while the Mac's Claude app is open, so treat them as backups. Cloud routines must NOT have connectors attached (clear with `clear_mcp_connections` after creating).
- Petit Le Mans morning update (cloud, cron repeated yearly): switched OFF Oct 15, 2026. Turn it back on only for 2027 (cron `0 10 1,2,3 10 *`).
- Portimao GT World Europe finale (Oct 16-17, 2026): cloud backups for the Friday and Saturday 6:30 AM ET "What to watch" updates (they check for the Mac task's entry first and skip if present). The Mac tasks (quali odds, race result, Friday/Saturday 6:00 AM) are primary this weekend.
- Live stream (hub "Watch here"): `netlify/functions/ytlive.mjs` finds the video live now on a series' YouTube channel (`yt` in `data/series.js`) through YouTube's Data API, using the `YT_API_KEY` environment variable set in Netlify (Site configuration > Environment variables; never in this repo). Without it the function falls back to reading the channel page, which YouTube blocks from servers with a bot check. A new env var only takes effect after a deploy.
- Live results (instant): `netlify/functions/gtwce.mjs` reads GT World Europe's official results pages; the hub shows them (`liveSrc`, `data/entries.js` `live:{round}`). Runs on Netlify, no computer needed.
- Automation that needs no computer (GitHub Actions, `.github/workflows/`): `race-weekend.yml` (every 30 min Thu-Mon) runs `tools/auto_update.py`, which for each `data/entries.js` entry with `live:{round}` refreshes the entry list, rebuilds the podium-game win chances once qualifying is published (`tools/podium_odds.py --quali`), imports the race classification into `data/results.js` (`tools/gtwce_result.py`, re-read for 2 days to catch penalties) and refreshes standings (`tools/gtwce_standings.py`), then commits to `main`. `standings.yml` refreshes GT World Europe standings every Monday. Shared parsing is `tools/gtwce_lib.py`. New GT World Europe Endurance weekends need no manual step: about 8 days before one that the app has an event for, `auto_update.py` finds the round on the series' entry-list page, creates the `data/entries.js` entry (with `live:{round}`) and fills the cars (`tools/gtwce_entries.py`). If it cannot (no entry list yet, site layout changed), the weekend is simply skipped; you can do it by hand with `python3 tools/gtwce_entries.py --round <slug>` after adding a skeleton entry. Sprint Cup weekends are not covered (different session structure). Formula 1 is covered by `tools/f1_update.py` (Jolpica F1 API = Ergast-compatible mirror of FIA results; formula1.com blocks servers): from 8 days before a Grand Prix at a venue the app has an F1 event for it writes the 'Pick your podium' entry in `data/entries.js` (drivers with their race numbers; win chances from form before qualifying, form + grid after: backtested on 2024-26), then the top ten into `data/results.js` as `#NUMBER Driver (Team)` and the standings into `data/standings.js` (a hand-written entry for the same race is kept). The game scores by `#NN`, so any new series' results lines must carry the car or driver number. IndyCar and GT World Challenge America are covered by their own readers, run from the same job: `tools/indycar_update.py` (INDYCAR's results API: top ten of the race, driver standings top 15 from indycar.com/Standings, and the venue's lap record if any session of the weekend beat it) and `tools/gtwca_update.py` (the series' results pages: race winner only, because the site lists just each session's top car; Pro / Pro-Am / Am driver standings top 6; practice and qualifying lap records). Both only act on races of the last 10 days at venues the app has an event for, write entries whose note starts with "(automatic update)", and NEVER overwrite a hand-written entry for the same race or season. GT World Europe also lowers lap records during a weekend (`gtwce_laprecords.py` `weekend()`, Barcelona counted from 2023: the map shows the no-chicane layout). Driver credit on automatic lap records follows qualifying order (qualifying N = N-th listed driver); check it against a series report when you can. IMSA has no machine-readable source we may use, so its results, standings and lap records stay manual. Other series need their own parser (and a backtest for the odds) before they can be added.

## Race weekend flow on the hub (Oct 26 2026)
- **A weekend stays "now" until the next morning.** `eventDone()` is true only after the last session AND `WEEKEND_GRACE_HOUR` (6:00 at the track, `graceEnd()`) the day after the event's last day (Monday morning after a Sunday race). Until then `focusAt()`, the Home tile, the series lists, the game card and the results cards still show the finished weekend; the hub's first card says "Weekend complete" and what is next here. A finished race keeps its results card for 6 hours or until the weekend is over, whichever is later.
- **Qualifying order and unofficial results** (series with `sess` in `data/series.js`; Formula 1 so far): `/api/session?s=f1&date=<race day>` (`netlify/functions/session.mjs`, routed in `worker/index.js`) reads the Jolpica F1 API (qualifying order and race classification, cached 30 s). The hub card `grid` ("Qualifying order": top five, tap for the full list in the `shRes` sheet) shows from the end of the series' last qualifying session until its last race ends, for the series in focus (`hubFocusSeries`); right after a race (even a few minutes before its scheduled end, once the feed has the classification) a "Unofficial results" card shows until our own `data/results.js` entry exists. The hub polls every 45 s while it is open (`sessWant`, `sessEnsure`), keeps the last answer in `K.sessFeed` for no signal. Grid penalties are not applied (the card and sheet say so). F1 Academy (`sess:"f1academy"`: the series' results pages carry the season's rounds and each session's results as `__NEXT_DATA__`, with `ResultsAreOfficial`, which the cards show; qualifying = "Qualifying 1") and Porsche Carrera Cup North America (`sess:"carrera"`: `porschecarreracup.us/results/` has every round's Practice/Qualifying/Race tables; the round comes from the `track` parameter and the year, the race from the number in the session `name`) are read the same way (the app sends `track` and `name` too). IndyCar is another series (`sess:"indycar"`): the same function reads INDYCAR's results service (`www.indycar.com/api/results/`: SeasonDropDown for the events, EventsSessionDetails per session; qualifying = "Combined Qualifying" or the qualifying session with the most cars, an oval shows average speed). GT World Europe already has its own live card (`gtwce.mjs`). FIA F2 and F3 (`sess:"f2"`/`"f3"`, SERIES guides added Oct 26 2026; `fiaformula2.com/en/racing/<year>/<venue>` embeds every session's start time and, for the LATEST completed session only, its results in the page's Next.js data (`results` rows with `version` Final or not); earlier sessions are remembered 4 days in the edge Cache API each time the page is read (`memoPut`/`memoGet`, only on the custom domain), so a session nobody read while it was the latest has no results; the venue slug is `FIA_SLUG[track]`; the Qatar 2026 F2 sessions come from that page's schedule, Abu Dhabi's were placeholders so they are not in yet; the schedule of every F2/F3 weekend can be filled from the same page once published) are read the same way. Readable but not built: SRO America / GT World Challenge America (practice and qualifying pages only: no per-car race page). GT2 and GT4 European publish PDFs only (a GitHub Actions poller writing a `live` branch could read them: the repository is public so raw.githubusercontent.com works; not worth building before their April 2027 rounds). The routine behind the series with no feed ("Trackside Pass: Results", hourly at :56, a persistent session) cannot be scheduled more often than hourly (the API refuses < 1 h), so a second copy, "Trackside Pass: Results (half-hour offset)" (trig_01GKEkDVqeei6cxJAwE4Y8Xx, created Oct 26 2026 through the API like the What to watch dispatcher: `sources` = this repository, no connectors, :26 UTC Thursday to Monday), runs 30 minutes later; together they check every 30 minutes. No source we may use found: IMSA and its series (imsa.com blocks servers; Alkamel is off limits), Porsche Supercup, MX-5 Cup, Lamborghini Super Trofeo, Masters, HSR: those rely on the hourly Results routine. Never read IMSA/Alkamel or any live timing data.
- **Points recap pop-up** (`maybeWeekendRecap()`, no push): once per game (`K.recapSeen`), when a game you made picks for has an official `RESULTS` entry and its race was within `RECAP_DAYS`; opened at launch, when the app returns to the foreground and when `refreshResults()` brings new results; "See my season" opens the Podium tab.
- **Automatic results and standings for the feed series** (Oct 26 2026): `tools/feed_results.py` (called by `tools/auto_update.py` every 30 minutes Thursday to Monday) writes the race result (top ten, note starting "(automatic update)") of F1 Academy, Carrera Cup North America, F2 and F3 from the `/api/session` feed for every finished race that `node tools/due_updates.js --results` lists (F1 Academy, F2, F3 only when the series marks the result official; Carrera Cup when the race is 60+ minutes old with 5+ cars); `tools/fia_standings.py` keeps the F2 and F3 drivers' standings (top ten, no team: the page lists none). The hourly Results routines (:26 and :56) stay as the fallback for anything still missing.
- **Video card**: "Watch here" only (no "free on YouTube" line, no "Open in YouTube" link); the YouTube fallbacks remain only for a series that forbids embedding.

## Pick your podium for every top series (Oct 26 2026)
The game is generic (one entry per series per weekend in `data/entries.js`, classes with cars `[number, team or driver, drivers/team, car, win chance %, basis, form]`, scored from `data/results.js` lines with `#NN`, locked at the first race session, published to Supabase by `tools/sync_games.mjs`, which scores the race session the picks lock at: `race` on a results entry names it, a lone entry also counts). How each series gets its entry:
- **F1** `tools/f1_update.py` (Jolpica; class "Race"); **GT World Europe** `tools/gtwce_entries.py` + `tools/podium_odds.py` (classes Pro, Gold, Silver, Bronze, live qualifying grid).
- **IndyCar** `tools/indycar_game.py` (INDYCAR's results service; class "Race"): field = the weekend's practice cars, else the latest race's field; chances = softmax of form (average finishing percentile over the last 6 races) before qualifying and form + qualifying grid after it; constants fitted on 86 races 2022-2026 (`ROAD` and `OVAL` in the script: winner log-loss -3.29 equal chances, -2.54/-2.70 form only, -2.08/-2.43 form + grid; calibration good from 1% to 40%). Results lines now carry `#NN` (`tools/indycar_update.py`). Not handled yet: the Milwaukee doubleheader (INDYCAR lists it as two events whose sessions are not named "Race").
- **GT World Challenge America** `tools/gtwca_game.py` (entry list `/entry-list/<year>/<round>` and `qualifying-1..3` pages of gt-world-challenge-america.com; classes Pro, Pro-Am, Am; GT World Europe's constants because this series publishes no per-car race results, so nothing could be re-fitted; the race result the site gives is the winner only, so a weekend scores the places the results entry names).
- **IMSA WeatherTech** (`gameManual:true` in data/series.js): no entry list a script may read (imsa.com blocks servers, Alkamel is off limits), so `node tools/due_updates.js` lists `why:"entries"` from 8 days before a weekend and the What to watch routine writes the entry (cars only, classes GTP, LMP2, GTD PRO, GTD) from the published entry list, then `python3 tools/game_odds.py <track> <day> weathertech` adds the chances (nearly equal inside each class, tilted by each car's finishes in the last 12 months of `data/results.js`, 0.5% floor). No grid is read, so they are not rebuilt after qualifying. Results for IMSA come from the Results routines (top three per class, class names exactly as in the entry: see the header comment of `data/results.js`).
